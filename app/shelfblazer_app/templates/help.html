Find something

Home and lists

  • Home: one search over every type: type words, part of a name, or an ID. Results are grouped by type; the tiles show each type’s size and a + to add.
  • Lists: search, sort by column title, filter by owner or archived, Table or Cards. The address holds your search and sort: bookmark or share it.
  • All words must match. Tick fuzzy for near spellings (only when there are few results, never for IDs). Archived entries are left out unless you tick archived.
  • Notes: only their beginning is searched; put searchable words in the name and fields.
    • {% if mcp_enabled %}
  • Your AI assistant can search too, in plain words: see below.
    • {% endif %} {% if sequences %}
  • Sequences: where a type has one, tick sequence and paste at least 6 bases: both strands are searched, Mismatches allows a few differences.
    • {% endif %}

Add something

Search first

Search the usual name and the name on the label or the paper: one thing is often written two ways. If the entry exists, use it; for a new stock of the same thing, add a note to it, or create an entry that links to it.

When you save, the app shows likely duplicates first. It only warns; you can save anyway. An archived duplicate is marked: that sample was most likely thrown away.

With your AI assistant

Describe what you have, in plain words: “Add these twenty {{ ex.type }}s from my table”. An AI assistant (Claude Code, for example) fills in the fields, checks for duplicates and follows the lab’s conventions; it can search too: “Which {{ ex.type }}s did I add this month?” It works as you, and its changes are marked “via MCP” in the History. Moving items to the lab collection, editing many records at once and files stay in the app.

With the form

  • + New opens a form made for the type; * marks required fields. Save and add another keeps you in the form.
  • Choice fields: use an existing option; add a new one (where offered) only if none fits.
  • Notes: simple Markdown: blank line for a paragraph, - lists, **bold**, *italic*, [text](https://…), IDs that link.
  • Files: 25 MB each, 5 at a time; programs and scripts are refused. A photo is shrunk in your browser; where the type shows a picture, it is the first image attached.
  • If someone saved the entry meanwhile, you are told and nothing is overwritten.

From a spreadsheet

For many entries at once, use Import… beside + New on a list. Download the empty template (the type’s column titles), fill it in, save it as CSV or TSV, upload it, match the columns and read the preview: every row is checked, and one bad row stops everything. Rows without an ID create new entries. Everything goes in as one commit that you can undo. To correct entries that already exist, see Change several at once.

IDs and labels

An ID is a two-letter type code, a hyphen and a number: {{ ex.prefix }}-12. It is given on saving and is never reused; write it on the label. Where a type is stored in ID order, the ID is the sample’s location. In notes, an ID written in full becomes a link; typed in a search box it opens the entry.

Links between records

A field that points to another record{% if ex.link %} ({{ ex.link.field }} in a {{ ex.link.type }}, pointing to a {{ ex.link.to }}){% endif %} takes IDs separated by commas; start typing to pick. The other record lists the link under Referenced by. Link rather than retype a name: a later correction then shows everywhere.

Change or retire something

Who can change what

  • Everybody with an account reads and adds records (an administrator can restrict this per type).
  • You edit, archive and restore your own entries; administrators edit all. Some types are open to everyone, or to administrators only; the entry says so when you cannot edit it.
  • Archiving hides an entry from everybody but its owner and the administrators; Restore brings it back. Links to it keep working. Nothing is ever deleted.
  • An administrator can change an entry’s Owner, for example when somebody leaves.

History and undo

Each change is saved with who and when, and listed under History on the entry. Open an earlier line to see the entry then, and copy values back through Edit. A bulk edit or an import is undone with the button shown right after it.

Many at once

Change several at once

In the app: press Select in a list, tick rows, Edit selected…, and set one field for all of them. You see what changes, and what is skipped because you may not edit it, before saving. One commit, with Undo right after.

In a spreadsheet, for anything more varied:

  1. Export. Select the rows, Export…, pick the columns (keep ID) and download a tab-separated file.
  2. Review and edit it in your spreadsheet program: correct values, fill gaps, add rows at the bottom. Leave the ID column as it is.
  3. Import it back with Import…: match the columns and read the preview. A row with an ID updates that entry (only if you may edit it); a row without one creates a new entry; an empty cell leaves the field alone. One bad row stops everything; the import is one commit, with Undo.

Scanning barcodes

Scan (sidebar; on phones, beside the menu) reads a code with the camera or a USB reader and opens the entry that carries it. For an unknown code you can add a new product with the code filled in, or add the code to an existing entry (same product, new package). Lot numbers start unticked. In a form, Scan beside a code field adds a code.

Your own collection

Where the lab allows it, you can keep your own items of a type, apart from the shared lab collection (My collection in the sidebar): work in progress, something you may not keep.

  • Choose where when you add: Add to lab collection or my collection (the lab by default).
  • They are not in the lab’s lists or counts. Also in collections, below a list, shows matches in your collection and others’; the Home search shows them in tables of their own.
  • IDs: you number yours from 1 with a P: {{ ex.prefix }}-P3 is your third. Someone else’s reads {{ ex.prefix }}-P3[Alice].
  • Who sees them: other people can read them by default. My account lets you hide each type; then only you and administrators see it. This is not secrecy (backups hold everything): keep nothing confidential here.
  • Links: lab records cannot link to a personal item; a personal item can link to lab records and to your own.
  • Move to the lab collection (on the item, or select several in a list): the page shows the new lab IDs first. Personal items it links to come along, or you link to a matching lab item instead. The old ID keeps working. You cannot undo a move; only an administrator can.
